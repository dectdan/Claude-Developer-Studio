## Decisions I made

1. **Where the "obvious" rule is written** (DEC002): in the start and status results (`MODE_GUIDANCE`, one line each mode), the `mode` parameter's description, the memory server's instructions (one more sentence: 825 → 1,261 characters), the reply result ("Tell the user what it asked and what you answered"), and the templates' `HOW_WE_WORK.md`. The workbench server got no `instructions` of its own (its tool results carry the rule where it's needed).
2. **Collaborative and delegated runs get a different start prompt.** P8's said "You are running unattended: nobody can answer questions", which is no longer true: someone answers. The new one keeps "follow the prompt's rules" and adds how to ask (a `QUESTION:` block, then stop). This changes the fixed start text (still built only from a validated phase name). Manual mode's first message is just "Read docs\<phase>_prompt.md and carry it out." (the user is there).
3. **Old runs without a mode** are shown as collaborative, with "(Started before modes existed: collaborative assumed.)"; `run-phase.ps1` runs show no mode.
4. **Manual mode starts the runner inside the visible window** (`node cds-phase.js --run … --manual`), which spawns Claude Code with the console inherited. So the runner's pid holds the lock, records the exit, and Stop's Ctrl+C reaches Claude Code (same console). It sets `--session-id <uuid>` so Status can find the transcript (`<config dir>\projects\*\<uuid>.jsonl`, searched by id) and Open-it can name it. No `--permission-mode`, no `--allowedTools`, no `--mcp-config`: the user's own Claude Code, as they'd start it. After Claude Code exits, the window shows a last note ("Claude Code has ended … claude --resume …") and closes 10 s later.
5. **Windows Terminal is started directly, not through WMI.** WMI's `Win32_Process.Create` can't start the `wt.exe` app alias (it returned 8, seen in T7's first try); WT hosts the window in its own process, so the runner's parent is `WindowsTerminal.exe` (checked), outside Claude Desktop's tree as WMI would make it. Without WT, the console window goes through WMI (`ShowWindow 1`); on Dan's PC that window was hosted by WT anyway (his default terminal). Found on the way: Node's `existsSync` says false for an app alias (a reparse point stat can't follow), so `lstat` is used.
6. **Stop on a manual run asks first.** Without `force` it returns what to tell the user (close the window or `/exit`); with `force: true`, two Ctrl+C half a second apart (an interactive session exits on a quick second press), else by force. The Dashboard's Stop button passes force (the user is the one clicking, after a confirmation dialog). Reply is refused for manual runs (the user answers in the window).
7. **Stop's sweep never ends a console host** (`conhost.exe`, `OpenConsole.exe`): in T2 it ended the window's host and closed the window before the runner's last note. Found in the real run, fixed, T7 showed the note.
8. **The index is `[Documents]\ClaudeDevStudio\phases.json`, not `%LOCALAPPDATA%`.** `claudedev_phase_start` runs inside Claude Desktop's server (a packaged app), and files a packaged process creates under AppData are redirected into the package (§11); Documents isn't, and the CLI already writes memory there from the same context. It is written at start and on each reply (newest first, 60 entries, one per project+phase); the runner records the outcome in the run's own `.json`. The tray polls every 15 s (one small index, one small `.json` per run of the last 14 days) rather than a file watcher on many folders; its first poll only remembers, so old runs don't pop up.
9. **"Recent projects from memory"** = the projects in `phases.json`, then folders browsed on the page (remembered in `HKCU\Software\ClaudeDevStudio\PhaseProjects`). CDS's memory folders are named by the project folder's name and don't record its path, so they can't be listed as paths; reading Claude Code's `~/.claude.json` for paths was ruled out (it's the user's Claude Code file).
10. **The Dashboard reads through `cds-phase.js`**, not a C# copy: `--status` (Status's own text) and `--conversation --json`. One parser of the log, tested by the smoke test against a fixture; the page and the chat always agree. It finds Node in Program Files and the installed `mcp-server` (`CDS_MCP_DIR` moves it, for development only); an installed copy older than P9 is named.
11. **Signed in?** `claude auth status` (exit 0 logged in, 1 not; its JSON names the account and is never shown or logged). Start refuses only on exit 1; anything else (an older Claude Code without the command, a timeout) doesn't refuse. Adds about a second to start.
12. **The user's "no" is remembered.** `claudedev claude-code remove` (and the tray's Remove, which runs it) passes `--remember-choice`, leaving `claude-code-declined.txt` beside `cds-claude-code.js`; the installer then shows the box unticked and a silent install doesn't set it up. Setup removes the marker; the uninstaller deletes it with the program. Without this, the new default would put the setup back on every upgrade.
13. **Too old (< 2.1)** is treated like not found on the finish page (box hidden, the line says `claude update`), since phases need 2.1.
14. **Sandbox E simulates Claude Code with a copy of `node.exe` at `%USERPROFILE%\.local\bin\claude.exe`** (where the native installer puts it): its `--version` prints Node's 26.13.1, which reads as new enough; nothing else runs it (setup edits `~/.claude.json` itself, as P4's test did). `auth status` on it fails, so status says not-signed-in; the check accepts ready/not-signed-in/not-set-up.
15. **`CDS_PHASE_WINDOW=hidden` and `CDS_TRAY_EVENT_LOG`** are new test-only variables (the manual window opened hidden; the tray's events written to a file whether or not Windows shows them).

## Facts used from Claude Code's docs

- **Interactive with a first message** (https://code.claude.com/docs/en/cli-reference): `claude "query"`: "Start interactive session with initial prompt". `--session-id`: "Use a specific session ID for the conversation (must be a valid UUID)". `--resume`, `-r`: "Resume a specific session by ID or name … When you pass a session ID, Claude Code searches the current project directory and its git worktrees, then every other project on this machine."
- **Signed in?** (same page): `claude auth status`: "Show authentication status as JSON … Exits with code 0 if logged in, 1 if not."
- **Transcripts** (https://code.claude.com/docs/en/sessions, "Where transcripts are stored"): "`~/.claude/projects/<project>/<session-id>.jsonl`, where `<project>` is your working directory path with non-alphanumeric characters replaced by `-`"; `CLAUDE_CONFIG_DIR` moves it; the entry format "is internal to Claude Code and changes between versions" (so the parser only reads `type`/`message.content`, as for the stream-json log, and skips `isSidechain`/`isMeta`). Resuming from a terminal (`claude --resume <id>`, no `-p`) "restores the permission mode the session was in"; `-p` sessions are left out of the picker but `claude --resume <session-id>` still opens them.
- **Install on Windows** (https://code.claude.com/docs/en/setup): PowerShell `irm https://claude.ai/install.ps1 | iex`; CMD `curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd`; WinGet `winget install Anthropic.ClaudeCode`; "log in by running `claude` and following the browser prompts"; uninstall paths show the native binary at `%USERPROFILE%\.local\bin\claude.exe`. `claude doctor` prints diagnostics without starting a session (not used).

## 2. Questions that come back cleanly

`parseQuestion(text)`: the last line starting `QUESTION:` (markdown `**`, `#`, `>` allowed), the question lines, options `1.`/`1)` with continuation lines, a recommendation line (`RECOMMENDATION:`, `I'd pick`, `I recommend`, …); all verbatim, trimmed. Status puts the block after the result in its own part ("It ends with a QUESTION (verbatim from the phase; relay it as written): / Question: / Options: / Its recommendation:"), capped at 2,400 characters and never cut by the 2,500 budget (the rest is shortened instead). Text without a block: the old rule ("It ends with a QUESTION (no QUESTION: block; read its text above)").

Templates: `HOW_WE_WORK.md`'s prompt skeleton has a new **Questions** section; "Writing and running a phase" has "Asking a question" (an example block, "not a question when the prompt's rules already decide it") and the three modes with the rule; `GROUND_TRUTH.md`'s Plan hint adds "asks only real decisions, with a `QUESTION:` block".
